# Rúbrica de demo — TaskFlow v3.0

> La usan **el feedback cruzado** (PM-1, MP-7) **y el instructor** (integrador). Regla del feedback:
> **2 fortalezas + 2 mejoras ancladas a un criterio** — prohibido el "estuvo bien".
> Modelo llenado de referencia: `../../solucion/rubrica-demo-ejemplo.md`.

## Escala

Cada criterio: **2 = sólido · 1 = a medias · 0 = ausente/falla**. Total sobre **16**.

| # | Criterio | Qué se busca | Puntos (0/1/2) | Nota anclada |
|---|---|---|:---:|---|
| 1 | **Problema y arquitectura claros** | Se entiende qué es y cómo está hecho (el diagrama hace el trabajo) | ___ | |
| 2 | **La demo viva corre** | Sobre los **datos del guion** (no genéricos); login→crear→PATCH DONE→GET encadena | ___ | |
| 3 | **Código explicado, no leído** | Una pieza con criterio; se cuenta el *por qué*, no se recita | ___ | |
| 4 | **Pipeline real mostrado** | Run verde del commit del tag + imagen en GHCR | ___ | |
| 5 | **Reparto 50/50** | Cambio de presentador en el punto 5; ambos hablan ~la mitad | ___ | |
| 6 | **Manejo de preguntas** | Cualquiera explica cualquier parte (incluye lo que no presentó) | ___ | |
| 7 | **OpenAPI legible** | Swagger con summary/description; ningún endpoint "abandonado" | ___ | |
| 8 | **Timing** | 10 min ±1, sin correr al final | ___ | |
| | **Total** | | **___ / 16** | |
